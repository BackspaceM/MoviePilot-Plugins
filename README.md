# MoviePilot-Plugins

MoviePilot **V3** 第三方插件仓库：<https://github.com/BackspaceM/MoviePilot-Plugins>

包含 18 个面向 MoviePilot V3 的插件，覆盖媒体库体检（整理预演、入库账本、
三家媒体库对比）、系统总览、源文件与媒体库对账、观影统计、媒体库维护、辅种、
插件维护以及一整套 RouterOS 网络管理能力。

## 安装与升级

把本仓库地址填入 MoviePilot 的 `PLUGIN_MARKET`（多个地址用逗号分隔），
插件市场只读取 `main` 分支的 `package.v3.json`。也可以直接 clone 到插件目录。

本仓库是第三方仓库，**没有 GitHub Release 发布包**，所以索引里每个插件都必须
声明 `"release": false`。宿主据此直接从 `plugins.v3/<插件ID小写>/` 拉取源码；
若误设为 `true`，宿主会先去找 `{插件ID}_v{版本}.zip`，失败后才回退，
日志里会出现 `Release 安装失败，回退文件列表安装`。

**升级步骤（按钮 404 时务必按此顺序做完）：**

1. 插件市场刷新索引，把**全部插件**更新到 `package.v3.json` 中的最新版本
   （只更新其中几个，未更新的插件仍会加载旧代码、按钮继续 404）。
2. **重启一次 MoviePilot 容器**：V3 动态路由只在插件加载/重载时注册，
   旧版本注册失败的路由不会自动恢复。
3. 确认容器日志中不再出现 `Error adding plugin route`，且
   `加载插件：<ID> 版本：<新版本号>` 与实际索引版本一致。
4. 回到插件详情页点按钮验证；若仍 404，先查日志里失败路由的类名是否还是旧
   `Response` 普通类——那说明插件文件根本没被更新。

### 媒体库体检：怎么用

**装好即用**。媒体服务器、下载目录和媒体库目录都是自动识别的，设置页只有一个可选的
「预演目录」，留空就从整理历史里推断。三页都是只读报告，明细完整列出、日志可复制。

**整理预演**：批量整理或改规则之前，先看看这批文件会落到哪个目录、会不会撞上已有的
同名文件、跨盘会不会让硬链接悄悄变成复制、是不是已经入库过。目标路径按「推断出的目录
\+ 保持原文件名」保守给出，实际命名仍由宿主整理链决定，插件一个文件都不动。

**入库账本**：把整理历史分页读全，用 `os.stat` 比对源文件和库文件的 inode 与设备号，
看硬链接到底是真链接还是已经退化成两份副本；再把源文件已删但库里还留着的、应删未删的、
两端都没了的、以及路径查不到的，分门别类列出来。源文件与库文件的对应关系会按剧集和季
理成一张表，顺带找出库里有、历史里却没记录的手工入库文件。

**媒体库对比**：把已连接的 Emby、Jellyfin、Plex 条目按 TMDB/IMDB/TVDB 编号对齐
（没有编号就用标题、年份和季集），列出哪家缺集、哪家多版本、哪些只存在一家。
连不上或路径看不到的都标「未核验」，不会当成这家没有。

详情页上方按钮切页，点「重新体检」强制重采，整理预演页还能单独重扫目录。
首页可以加「媒体库体检」组件看汇总。外部接口：`GET /snapshot`、`POST /refresh`、
`POST /view`、`POST /preview`、`GET /log`。

插件只读，不创建、移动、重命名、删除任何文件，也不改整理历史、下载器任务与媒体服务器，
更不会触发媒体库刷新。`tests/v3/librarycheckup/run_stub_tests.py` 有 63 个离线用例，
覆盖三页各分支、真实硬链接端到端、按钮契约、转义、密钥不泄露与零写入约束。

### MP 总览：怎么用

**装好即用，设置页只有一项「首页自动刷新」间隔**，媒体服务器、下载器、订阅、
入库与插件状态全部从 V3 稳定只读接口自动读取，无需填地址和密钥。插件只读，
不会修改配置或媒体文件。

- **详情页**：插件卡片点开即是完整看板，点「刷新数据」由宿主重新拉取页面。
- **首页仪表盘**：在首页「添加组件」里选择「MP 总览」（`get_dashboard_meta()`
  提供的 `overview`），按设置间隔自动刷新；紧凑布局会隐藏系统/运行状态明细。
- **外部调用**：`GET /api/v1/plugin/MPOverview/snapshot` 返回 JSON 快照，
  `POST /api/v1/plugin/MPOverview/refresh` 清缓存强制重采。

数据源不可用时会显示占位符并标注「离线预览」，不会把缺失数据伪装成 0。

### 入库对账：怎么用

面向 PT 连载番剧的真实痛点：单集做种，完结后出合集打包、站点要求删除单集种子，
于是「种子删了、源文件删了或还留着、媒体库里硬链接入库的文件还在」。
插件用**两条互补路径**把它查清楚，并且所有清单都**全量输出、不截断**。

**① 整理历史对账**：逐条比对「源文件 ↔ 媒体库文件 ↔ 种子状态」，按剧集 / 季聚合。

| 状态 | 含义 |
| --- | --- |
| 源已删 · 库仍在 | 打包删种后的孤儿入库，已无法继续做种 |
| 源残留 · 种已删 | 源文件与库文件都在、下载器已无对应种子，可核对后清理 |
| 库文件缺失 | 有整理记录但媒体库目标文件已不在 |
| 双端已无 / 待核对 / 正常 / 未核验 | 其余状态；未核验不会推断为已删除 |

**② 主动扫描（下载器 ↔ 映射路径）**：读取下载器**完整种子名录**（种子名称、hash、
内容路径），遍历映射目录里的实体媒体文件，找出「种子已删但源文件还占空间」的残留。
页面会完整列出：

- **种子名称清单**——一键复制，直接粘到下载器搜索框逐个核对种子是否真的没了；
- **完整核对清单**——每条含种子名 / hash / 状态 / 源路径 / 库路径；
- **映射目录扫描结果**——全量文件表格，带状态筛选与勾选框；
- **下载器种子名录**、**全量需关注明细**、**源残留路径清单**；
- **操作日志**——常驻页面，同时写入 `logs/plugins/transferaudit.log`，
  在插件卡片点「日志」也能看到，日志末尾同样附可复制的种子名称清单。

**设置（只有 4 项，留空即用）**：

| 设置 | 说明 |
| --- | --- |
| 源目录 | 容器内可见的下载目录，每行一个；留空自动从下载器保存路径与整理历史推断。系统目录与一级目录会被拒绝 |
| 路径映射 | `下载器路径=容器路径`，如 `/volume1/download=/downloads`。两边路径不一致时必填，否则种子名录匹配不上会**自动禁用删除** |
| 启用源文件删除能力 | **默认关闭**，开启后详情页才出现高危提示与删除按钮 |
| 删除方式 | 默认「移入隔离目录（可恢复）」，也可显式选「直接删除（不可恢复）」 |

**删除流程（默认关闭，开启后强制三步）**：

1. 扫描出完整列表（只读，绝不自动删除）。
2. 点「① 生成删除预览」——**不删除、不移动任何文件**，只生成一份带编号的清单；
   或在文件表格里勾选后点「删除勾选项」，会有两次浏览器确认。
3. 看清提示后点「② 确认删除」才真正执行，单批最多 10 个，逐条复检、逐条记日志。

> **⚠️ 此操作非常危险，可能导致不可逆的数据丢失！** 删除的是**下载目录里的源文件**，
> 不是媒体库文件。默认移入 `<扫描目录>/.transferaudit-trash/<时间>/`，可自行还原；
> 选「直接删除」则不可恢复，请务必先复制种子名称到下载器逐一确认。

**安全边界**：下载器名录读取失败、扫描到的文件一个都匹配不上种子（路径映射可疑）、
文件在扫描目录之外、属于媒体库文件、仍是符号链接或仍被种子覆盖时，**整批拒绝执行**；
执行前后各复检一次种子名录，任一条失败即停止，不做部分删除。远程存储
（u115 / alipan / rclone / alist 等）与容器内不可见的路径一律标「未核验」，
绝不把「查不到」当成「已删除」。插件不会改动整理历史或下载器任务。

- **首页仪表盘**：添加组件「入库对账」，每 120 秒自动刷新紧凑视图。
- **外部调用**：`GET /snapshot` 完整 JSON；`POST /refresh` 强制重扫；
  `POST /scan` 只重扫下载器与映射目录；`GET /log` 可复制日志与种子名；
  `POST /prepare` 生成预览（不删文件）；`POST /delete` 需 `plan_id` + `confirm` 口令。

## 目录结构

```text
plugins.v3/<plugin_id_lower>/   V3 插件源码（目录名 = 主类名小写）
tests/v3/<plugin_id_lower>/    离线 stub 测试
tests/v3/check_api_contract.py 全仓 API 契约校验
icons/                         统一风格图标（PNG + SVG 矢量源）
package.v3.json                V3 插件市场索引
```

## 开发约定

- 主类定义在 `__init__.py`，继承 `app.sdk.plugin._PluginBase`；目录名为主类名小写。
- `plugin_version`（类内字符串字面量）、`package.v3.json` 的 `version` 与最新
  `history` 三者保持一致；历史按语义版本降序、当前版本置顶。
- **插件 ID 与类名一经发布不得修改**（会导致已安装配置丢失），改名只改显示名。
- 图标统一为 `icons/<小写目录名>.png`（256×256），并保留同名 `.svg` 矢量源。
- 插件运行数据写插件数据目录，不写回源码目录；第三方依赖写在 `pyproject.toml`。

### V3 插件 API 契约（详情页按钮不 404 的关键）

宿主的动态路由注册等价于对 `get_api()` 的每条声明执行
`FastAPI.add_api_route(**api)`，失败时只写日志、跳过该路由：

1. `path` 用相对路径（如 `/run`），宿主自动补成 `/api/v1/plugin/<插件ID>/run`。
2. **endpoint 的返回注解必须是 Pydantic 可识别的类型**（`BaseModel` 子类、
   `dict`、`Any` 等）。普通 Python 类会触发
   `FastAPIError: Invalid args for response field`，路由被静默跳过，
   按钮点击即返回 404 Not Found。
3. 按钮 `events.click.api` 写 `plugin/<插件ID>/<action>`，`method` 必须与
   `get_api()` 的 `methods` 匹配；所有接口声明 `auth: "bear"`。
4. 返回统一三段式 `{success, message, data}`，前端普通数据客户端会严格校验。

## 校验

```bash
python3 tests/v3/check_api_contract.py
for f in tests/v3/*/run_stub_tests.py; do python3 "$f"; done
```

`check_api_contract.py` 会离线加载全部插件，按宿主方式用 FastAPI 注册每一条动态路由，
并逐项核对详情页按钮的路径与方法；还会向插件注入多种数据状态反复调用 `get_page()`，
把只在「有数据」分支里才出现的按钮也纳入扫描。任何注册失败、按钮引用不存在的接口
或方法冲突都会以非零退出码报错。它需要本机有 `fastapi` 与 `pydantic`，
不需要 MoviePilot 宿主。

`tests/v3/mpoverview/run_stub_tests.py` 额外覆盖首页仪表盘三元组、设置项数量、
离线采集、HTML 转义与响应模型类型。

`tests/v3/transferaudit/run_stub_tests.py` 共 61 例，额外覆盖：对账状态全部分支、
远程存储与路径不可见时的防误报约束、分页与空库/离线区分、下载器查询失败降级、
路径映射与危险根目录拒绝、种子名/日志可复制、全量清单不截断；以及用**真实临时目录**
跑通「扫描 → 预览（不删）→ 二次确认 → 移入隔离目录」的完整删除链路，
并逐项验证只读模式、错误令牌、错误口令、下载器失联、越界路径等拦截门槛。
