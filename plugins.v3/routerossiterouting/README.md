# RouterOS 站点智能分流 / DNS

读 MoviePilot 站点管理里已配好的站点，主域名、Tracker 域名、api_domain、ext_domains
都收进来；下拉里勾选，或者按 `名称|主域名|Tracker域名|备注` 手填几行，两者同名时
手填的优先。V3 的 SitesHelper、旧路径、用户站点记录挨个试，读不到就留空，不会在
加载插件时报错。

写五个分区：`/ip/dns/static` 把每个域名指到填的解析目标 IP（通常是 CF 优选出来的
那个），`/ip/firewall/address-list` 把域名放进地址列表，`/ip/firewall/mangle` 打
连接标记和包标记，`/ip/route` 按网关建策略路由，`/ip/firewall/filter` 放行。
mangle、策略路由、放行都能单独开关，策略路由要填网关。

每条都带 `MP-B3[站点id:用途] 中文含义` 的备注。同标签已存在就跳过，重复点部署
不会堆重复规则；部署前在 RouterOS 留一份 `.backup`，MP 侧存一份结构化快照，中途
写失败就逆序删掉本次新建的条目。回滚也只删这些带标签的，手工规则不碰。mangle
和策略路由算中高风险，没勾「允许高风险动作」就不生成计划。

站点增删按标签走增量同步。cron 默认每天 5 点，到点重新发现站点、比对设备现状、
没校验错误才下发；开了「清理失效站点条目」才会删掉设备上还带着 MP-B3 标签、
但当前清单里已经没有的旧条目，删之前同样先备份。想立刻跑一次就点「立即同步一次」。

几个限制：RouterOS v6 没有 REST，只有 v7 能用；规则顺序以设备上现有链为准，
mangle 和放行规则要排在兜底 drop 之前才生效；跟 CF 优选 IP 插件一起用时，同域名
的 static DNS 只留一条，不重复新增，地址列表和标记配合那边选出来的 IP 用；
改完最好在 WinBox 里核一眼顺序。
