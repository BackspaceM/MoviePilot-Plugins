# RouterOS 配置备份与漂移检测（RouterOSConfigGuard）

定时备份 MikroTik RouterOS（v7 REST API）的关键配置分区并生成快照，与基线做**指纹对比**，
检测配置的**新增 / 删除**并高亮敏感分区（防火墙、NAT、路由、DNS、用户、脚本等）。
备份落点可选：MP 插件目录、RouterOS 本机，或两处都存。漂移或备份异常时通过 MP 通知推送。

配置改来改去，出问题时很难说清到底改了什么。这里把分区读成快照，去掉 `.id` 和一直在变的统计字段，
只比真实配置，敏感分区一变就告警。想留个整机灾备，也能让路由器自己存一份 `.backup` + `.rsc`。

## 配置

### 1. RouterOS 连接
- 地址填 `192.168.1.1` 或 `https://ros.local`；端口默认 443，可切 HTTP。
- 用户名需具备 **read / api / rest-api** 权限；若要在 RouterOS 本机生成备份，
  该用户还需 **write / policy** 权限（`/system/backup/save`、`/export` 是写操作）。
- 用自签证书就保持"使用 HTTPS"开着（插件对自签证书不做强校验，与 CFRouterOS 一致）。
- 保存前可用详情页「测试连接」验证。

### 2. 备份分区（下拉多选）
默认勾选 12 个常用分区；另有 DHCP 租约、Mangle、服务端口、系统用户/计划任务/脚本等可加选。
**敏感分区**（路由、DNS、防火墙、地址列表、服务、用户、脚本、计划任务）一旦漂移会高亮告警。

### 3. 备份位置
用「备份存放位置」下拉选择归档文件落在哪里：

| 选项 | 说明 | 产物 |
|---|---|---|
| **仅 MP 插件目录**（默认） | 结构化 JSON 快照，可程序化对比、可回滚查看 | `snapshots/*.json` |
| **仅 RouterOS 本机** | 调用路由器原生备份，文件留在路由器 flash | `<前缀>_<时间戳>.backup` + `.rsc` |
| **两处都存** | 上面两份都要 | JSON + `.backup`/`.rsc` |

- RouterOS 端：`.backup` 是**二进制系统备份**（可整机等比例恢复，含证书/设备信息）；
  `.rsc` 是**可读配置导出脚本**（可跨设备迁移片段）。两者用同一时间戳前缀成对生成。
- **加密**："加密 RouterOS 备份"默认开启，并填写"备份加密密码"。
  `.backup` 不加密会带上账号和证书，这个开关别关（密码在日志和通知里会脱敏）。
- **文件名前缀**：默认 `rosguard`，用于识别本插件生成的备份并做轮转；不要与其它备份重名。
- **保留份数**：同时控制 MP 快照份数与 RouterOS 本机备份**组数**（一组=`.backup`+`.rsc`），
  超出后按时间倒序删除最旧的。轮转**只删本插件前缀**的文件，不碰路由器上其它文件。

漂移检测用的基线是轻量的检测状态（几十 KB），不管备份存在哪，它都留在 MP，只用来做对比，不算备份归档。
只存路由器时，MP 里也会留最近一轮快照，给「最近设为基线」用。

### 4. 基线与周期
- **首次自动设基线**：无基线时把首份快照设为对比基准。
- `cron` 默认 `0 3 * * *`（每天 03:00）；`*/5 * * * *` 表示每 5 分钟。
- 「最近设为基线」可随时把最新一轮设为新基准（例如确认一次大改是合理的之后）。
- 「清空快照」只清 MP 侧的快照/基线，**不会删除 RouterOS 本机文件**，避免误删灾备。

## 漂移判定

1. 每个分区的每一行配置，剔除易变字段（`.id`、`bytes`、`uptime`、`rate` 等）后做稳定 SHA256 指纹。
2. 快照保存为 `{分区: [指纹列表 + 规范化行]}`。
3. 当前快照与基线按指纹**多重集**对比：同一指纹出现次数一致即视为未变；
   多出来的记「新增」、缺少的记「删除」。修改某个字段必然表现为「一行删除 + 一行新增」，语义更强。
4. 通知/详情页输出按分区分组的差异明细，敏感分区带 ⚠ 标记。

> 例：把 `a.local` 的解析从 `1.1.1.1` 改成 `8.8.8.8`，会报告 DNS 静态记录 `+1 / -1`。

## 怎么用

1. 安装并启用插件，填 RouterOS 地址/账号，选备份分区与备份位置。
2. 点配置页「立即执行一次」（或详情页「立即备份并检测」）生成首份快照并自动设为基线。
3. 之后由 cron 定时检测；发生漂移、RouterOS 备份失败时收到 MP 通知。
4. 若某次变更是预期的，点「最近设为基线」以新快照为基准，避免持续告警。
5. 需要核对路由器上的实际备份时，点详情页「刷新ROS备份」从 RouterOS 实时拉取文件清单。

## 详情页 / API / 远程命令

- **详情页**：插件状态、备份位置、基线时间、MP/ROS 双清单、最近漂移明细、INFO 级实时日志，
  以及「立即备份并检测 / 测试连接 / 最近设为基线 / 刷新ROS备份 / 清空快照 / 停止」按钮。
  （日志与明细中的动态文本已做全角转义，不会被前端当 Markdown 渲染成空占位。）
- **API**（前缀 `/plugin/RouterOSConfigGuard`）：`/run` `/test` `/baseline` `/snapshots`
  `/rosbackups` `/status` `/clear` `/stop`。
- **远程命令**：`/rosguard_status` `/rosguard_run` `/rosguard_baseline` `/rosguard_clear`。

## 读写边界

- 漂移检测的分区读取对 RouterOS **只读**（GET）；仅当选择 RouterOS 本机备份时才执行写操作
  （`/system/backup/save`、`/export`），用于生成灾备文件。
- 密码（RouterOS 登录密码 + 备份加密密码）在日志与通知中脱敏；快照 JSON 不存任何登录凭据。
- 备份轮转只删除本插件前缀的文件；RouterOS 端删除按 `.id` 精确操作，不误伤其它文件。
- 试运行模式只读取并输出漂移结论，不落盘、不生成 RouterOS 备份、不更新基线。

## 依赖

MoviePilot V3（>=3.0.0）。无额外第三方依赖；RouterOS 端备份使用 v7 REST API（不依赖 routeros-api 库）。
