# Reseed 辅种（ReseedCrossSeed）

MoviePilot V3 插件。扫描下载目录，用「文件名 + 大小 + 目录结构」生成索引，
交给 [Reseed](https://github.com/tongyifan/Reseed-backend) 服务找出各站同内容种子，
下载 `.torrent` 后复核文件清单，一致才按原路径加进下载器做种，不需要重新下载文件。

> 和仓库里另外两个辅种插件不是一回事：`NameCrossSeed` 按标题召回、`PiecesHashReseed`
> 按 `sha1(info.pieces)` 内容指纹去各站查询；本插件不读 `.torrent` 缓存，
> 只把本地文件清单交给中心服务，由它返回「哪个站哪个种子可以辅种」。

| | 起点 | 指纹 | 匹配方 |
| --- | --- | --- | --- |
| 名称辅种 | 下载器里的种子 | 发布名 + info_hash / 文件清单 | 逐个站点搜索 |
| Hash 辅种 | `.torrent` 缓存文件 | pieces hash | 各站 `pieces-hash` 接口 |
| Reseed 辅种 | 磁盘上的文件 | 文件名 + 大小 + 目录结构 | Reseed 中心服务 |

## 开始前

1. **Reseed 账号**：官方服务 `https://reseed-api.tongyifan.me/`，注册需要用指定 PT 站验证；
   也可以自建 `Reseed-backend`，把「服务地址」改成自己的地址即可，接口契约一致。
2. **扫描目录**：填 MoviePilot 容器里能看到的下载根目录（每行一个）。插件只扫顶层项，
   目录里的文件按相对路径与大小建索引，`.torrent`、隐藏文件和常见无关格式自动跳过。
3. **站点映射**：每行 `Reseed站点名:MP站点名:Passkey`。Reseed 站点名可在详情页点
   「检测服务」看到收录列表；MP 站点名要和站点管理里的名字一致；Passkey 用于拼种子下载链接。
4. **下载器**：默认用第一个可用下载器，也可在设置里指定。目标下载器必须能看到同一份文件。

## 配置

| 配置项 | 说明 |
| --- | --- |
| 启用插件 / 试运行 / 发送通知 / 包含部分匹配 | 试运行只统计不加种；部分匹配默认不处理，打开后仍需通过文件清单复核 |
| 服务地址 / 账号 / 密码 | 官方地址已预填；密码只用于登录取 token，日志与接口响应不回显 |
| 扫描目录 | 每行一个下载根目录 |
| 站点映射与 Passkey | 每行 `Reseed站点名:MP站点名:Passkey[:下载模板]` |
| 参与站点 | 逗号分隔 Reseed 站点名，留空＝映射里全部 |
| 辅种目标下载器 | 可手填下载器名，留空用第一个可用下载器 |
| 定时方式 / 执行周期 / 固定间隔 | cron 为 5 段；官方服务有限流，默认「禁用」，建议手动或每天一次 |
| qBittorrent 跳过哈希校验 / 添加后自动开始做种 / 辅种标签 | Transmission 会自动重新校验 |
| 单次最多辅种数 / 请求超时 | 流控与运行保护 |

## 怎么跑

```
扫描目录顶层项 → 生成索引 JSON（纯 ASCII）→ 登录取 token → 拉收录站点
    → POST upload_json（索引 + 站点列表）→ 拿到 cmp_success / cmp_warning 里的「站点名-种子ID」
    → 按 MP 站点配置拼下载链接 → 下载 .torrent → 解析 info_hash 与文件清单
    → 去重（下载器已有 hash / 历史成功记录）→ 文件清单严格复核
    → 暂停状态添加到下载器（原路径 + 标签 + qB 跳验）→ 启动做种 → 统一落盘统计
```

服务端判定「完全匹配」时允许 ±5% 的大小误差，本插件在添加前会再做一次**精确复核**：
文件名集合与大小必须全部对上（自动兼容站点种子带或不带顶层目录名），对不上就跳过并记日志。
索引内容没变化时直接复用 24 小时内的命中结果，不重复上传——官方服务限制每小时 5 次、每天 10 次查询。
想强制重新查，在详情页点「清除缓存」。

## 按钮与接口

| 按钮 | 作用 |
| --- | --- |
| 立即辅种 | 后台跑一轮，命中且复核通过会添加种子 |
| 试运行一次 | 只统计命中与可辅种数量，不下载不加种 |
| 检测服务 | 登录 + 拉收录站点，直接回报账号或服务哪里不对 |
| 清除缓存 | 清掉命中结果与已辅种记录，下次运行重新查询 |
| 刷新状态 | 回报最近一轮摘要 |

接口前缀 `/api/v1/plugin/ReseedCrossSeed/`，动作 `run` / `dryrun` / `probe` /
`clear_cache` / `status`，全部 `bear` 鉴权。远程命令 `/reseed` 等价于 `/run`。

详情页只读状态、不轮询、不显示日志；逐组过程和失败原因在插件卡片右上角「…」→ 查看日志。
插件后台线程会尝试绑定插件实例，配合 MP 的「插件实例日志等级覆盖」，
全局日志等级设成 WARNING 时也能单独看这个插件的 INFO 日志。

## 限制

- 必须有可用的 Reseed 服务和账号，服务端没收录的站点不会返回命中。
- 文件名与大小必须一致，站点重新打包改名、改文件结构都无法匹配；这点和 pieces hash 一样。
- 跨下载器辅种要求目标下载器能看到相同路径下的文件，否则会停在校验失败状态。
- 不要和 IYUU、名称辅种、Hash 辅种对同一站点同时启用，避免重复添加。
- Passkey、密码只用于请求，日志里脱敏，接口响应不回显。
